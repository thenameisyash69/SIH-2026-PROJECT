# Known Limitations — stated plainly, per the project's own honesty principle

## Data
- **The facility registry (12 sites) is a curated demo set, not a national
  database.** It does not represent India's full industrial landscape. Every
  facility record carries `source: "curated_demo"` so this is never implied
  otherwise anywhere in the API or UI.
- **Most data in the system by volume is synthetic** (`source: "demo_synthetic"`),
  generated by `backend/scripts/seed.py`, until real FIRMS ingestion has been
  run repeatedly over time. Real and demo data are tracked separately in
  every stats endpoint and never combined into one headline number.
- Land-cover tagging depends on OpenStreetMap coverage, which is uneven across
  rural India — a location with no OSM tags nearby returns `"unknown"`, which
  correctly reduces classification confidence rather than guessing.

## Statistical thresholds
- Baseline deviation thresholds (1.5σ / 2.5σ) and the minimum-8-observations
  rule for a valid baseline are reasonable statistical conventions, **not
  operationally validated against real incident outcomes.** They should be
  tuned once verified incident data exists (see `/hotspots/{id}/verify`).

## Machine learning
- The trained classifier (when present) uses a small, hand-picked feature set
  (6 features) and is trained on data that is majority-synthetic until real
  ingestion accumulates. Its `predict_proba()` output is reported as a
  **"model score," not a calibrated probability.**
- With only 12 facilities, even a facility-aware train/test split has limited
  statistical power — reported metrics should be read as directional, not
  as production-grade validation. See `docs/ML_EVALUATION.md`.

## Attribution
- A thermal observation being geographically near a facility **does not prove**
  the facility is the source — `distance_to_facility_km` is always shown, and
  language throughout the system says "associated with nearby industrial
  infrastructure," never "confirmed at this facility."
- The system does not verify facility ownership, operational status, or
  ground-truth fire boundaries. VIIRS pixel resolution (~375m) means a single
  detection covers an area, not a precise point.

## What was deliberately not built (see IMPLEMENTATION_AUDIT.md for full P-ranking)
- No authentication/authorization — acceptable for a hackathon demo, not for
  production deployment.
- No automated test suite yet.
- Docker Compose is written but has not been run end-to-end in this
  environment (no network access during development).
- No production-scale facility ingestion pipeline (OSM-derived or otherwise)
  — the schema supports it (`source: "osm_derived"`), but the ingestion job
  itself was not built, to keep hackathon effort on the intelligence layer.

## Added this pass (live data / ingestion)

- **No real FIRMS data has been ingested in this development environment.**
  A `FIRMS_MAP_KEY` was never configured in this sandbox (no network access
  to test one against), so `/data-sources/status` will correctly show
  `OFFLINE — NASA FIRMS` and `total_real_observations: 0` if queried right
  now. This is not a bug — it's the honest state, verified by
  `tests/run_pipeline_scenarios.py` Scenario I.
- **Duplicate detection matches on exact acquisition timestamp** + rounded
  coordinates + source. NASA's Area API can occasionally return the same
  physical detection with a slightly different `acq_time` rounding between
  requests in rare edge cases — this would NOT be caught as a duplicate.
  Not fixed in this pass; documented as a known gap.
- **`datetime.utcnow()` is used throughout** (models.py, pipeline.py, etc.)
  and raises a `DeprecationWarning` under Python 3.12+ (confirmed during
  test runs in this pass). Functionally correct today; should migrate to
  timezone-aware `datetime.now(timezone.utc)` before this becomes a hard
  error in a future Python version. Not fixed in this pass (cosmetic/future
  maintenance item, not a correctness bug).
- **Satellite Evidence Viewer (spec Phases 13-16: zoomed event view, cloud/
  quality-aware scene selection, true-color/infrared modes) was NOT built
  in this pass** — explicitly deferred per the instruction to get live data
  ingestion working first. `SatelliteThumb.jsx` still shows a single NASA
  GIBS snapshot with no quality assessment or scene-selection logic.
